# Decision log

Why the template is built the way it is, and what was rejected. Add an entry when you change a foundation.

| # | Decision | Chosen | Rejected (and why) |
| --- | --- | --- | --- |
| 1 | Platform | **Expo SDK 58** (React Native 0.88, React 19.3), New Architecture, React Compiler | Bare React Native CLI: more native maintenance, no config plugins, CNG or EAS integration |
| 2 | Package manager | **pnpm 11**, `nodeLinker: hoisted`, `trustPolicy: no-downgrade` | npm/yarn: slower, no supply-chain trust checks. Isolated pnpm layout: Metro and autolinking edge cases |
| 3 | Structure | **Feature-first**, thin routes, `@/` alias | Layer-first (`screens/`, `services/`): scatters a feature across folders and makes removal hard |
| 4 | Navigation | **Expo Router**: typed routes, **native tabs**, native stacks, `Stack.Protected` gating | JS tabs (non-native feel, JS-thread work). `<Redirect>` in layouts (wrong-screen flash). React Navigation directly (no file routing or typed links) |
| 5 | Environments | Zod-validated `env.ts` → `expo.extra.env`; files in `env/` | Root `.env.*` (Expo CLI auto-loads them by NODE_ENV, mixing environments). `EXPO_PUBLIC_*` everywhere (inlined, unvalidated) |
| 6 | Styling | **Uniwind** (Tailwind v4) + **React Native Reusables** components + `cva` | NativeWind (Uniwind chosen for CareLink parity and its Tailwind v4 / CSS-first theming). Unistyles (no Tailwind classes, less shadcn parity). Two variant systems (CareLink's `tv` + `cva`) |
| 7 | Tokens in JS | `useColorToken()` reads live CSS variables | A JS mirror of the tokens (two sources that drift) |
| 8 | Icons | **lucide-react-native** through one `Icon` wrapper and **per-icon deep imports** | The barrel import: bundles all ~1,900 icons, +2.1 MB of bytecode (measured). Hugeicons: available as a swap recipe |
| 9 | Switch | React Native's **native `Switch`**, colored by tokens | `@rn-primitives/switch` (a JS-drawn switch with less native feel) |
| 10 | Toasts and haptics | **sonner-native** behind `lib/toast`; `expo-haptics` behind semantic `lib/haptics` | Hand-rolled toast. `react-native-flash-message` (dated, no stacking). `burnt`: kept as the fallback |
| 11 | Data fetching | **TanStack Query v5** + Axios, `queryOptions` + key factories | SWR (weaker mutations and persistence). RTK Query (needs Redux). Apollo/urql (GraphQL only). `react-query-kit` (redundant with `queryOptions`). TanStack DB / sync engines (0.x or backend-specific; offline-first recipe only) |
| 12 | Errors | One `ApiError` type, normalised in the client | Raw `AxiosError` in screens (inconsistent handling and messages) |
| 13 | Validation | Zod: always strict at trust boundaries; large lists validated in dev and preview only | Validating every payload in production (CPU on low-end Android). Never validating (silent crashes later) |
| 14 | Forms | **TanStack Form** + Zod via `createFormHook` (bound fields) | react-hook-form (fine, but TanStack Form matches CareLink web and mobile and is type-safe end to end). Hand-wired `value`/`onChange` everywhere |
| 15 | Client state | **Zustand** + MMKV persist | Redux (boilerplate). Context (re-renders everything) |
| 16 | Storage | **MMKV v4** for app data; **expo-secure-store** for tokens | AsyncStorage (slow, async). Tokens in MMKV (plain on disk) |
| 17 | Auth refresh | Single-flight refresher with a bare refresh client; network failures keep the session | Refresh per request (a stampede). Signing out on any refresh error (flaky networks log users out) |
| 18 | Offline | Opt-in persisted queries (`meta.persist`), buster and maxAge; mutations **fail fast** by default, queue opt-in | Persisting everything (stale or other-user data, slow restore). Queueing every mutation (unsafe for non-idempotent actions) |
| 19 | OTA | EAS Update channels per profile; `fingerprint` runtime version (skipping `extra`) | `appVersion` runtime policy (manual and error-prone). Updates shared across channels (QA leaks to production) |
| 20 | Lint and format | ESLint flat config (antfu, formatting included), React Compiler rules, `better-tailwindcss`, `type` over `interface` | Prettier plus ESLint (two tools). Interfaces (break `Record<string, unknown>` constraints, e.g. React Query `meta`) |
| 21 | Tests | Jest + RNTL 14 + **MSW v3** through the real client; explicit Reanimated mock; contrast test on tokens | Mocking axios directly (skips interceptors). Installing `react-native-web` for tests (blocked by a trust check on `ua-parser-js`, an unnecessary dependency) |
| 22 | E2E | **Maestro** | Detox (heavier setup and maintenance for a starter) |
| 23 | Example backend | **dummyjson.com**: real JWT, refresh, pagination, authenticated `auth/*` resources | A local mock server (more setup, nothing real to verify against) |
| 24 | Icon badges | Pre-generated by a script, committed | The `app-icon-badge` config plugin (races the Android icon step on EAS) |

## Outcomes recorded during implementation

- **SDK version:** planned for SDK 57. `create-expo-app@latest` produced SDK 58, which matched the "latest stable" requirement.
- **Native tabs:** stable on SDK 58 (`expo-router/native-tabs`), so no fallback was needed.
- **Android heap:** the local Android build needed a larger Gradle heap → `plugins/with-gradle-memory.js`.
- **Contrast fix:** the contrast test caught light `destructive` on `muted` at 4.39:1, and the token changed to `#d42424`.
- **Icon bundle cost:** the icon barrel was found with Expo Atlas, and per-icon imports are now lint-enforced.
- **Inline requires:** Metro's `inlineRequires` is off in Expo's defaults and left off. It's documented as a measured opt-in ([performance.md](./performance.md)).
